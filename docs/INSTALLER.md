# Установщик II+

`dist/II-Setup.exe` — загрузчик и установщик для Windows 10/11 x64 с .NET Framework 4.8.
Python устанавливать отдельно не нужно. Требования самого приложения, включая
драйвер NVIDIA для CUDA и Microsoft Visual C++ Runtime, описаны в PORTABLE.md.

Установщик содержит зафиксированные SHA-256 и размеры частей конкретной сборки.
Он скачивает 1–4 части одновременно (по умолчанию 2), продолжает прерванные
загрузки, проверяет все части, распаковывает ZIP прямо из них и создаёт ярлык.
При ошибке старые установки остаются нетронутыми. Выбирайте новую папку.
Права администратора не нужны при установке в доступную пользователю папку.

Пока идёт установка, на выбранном диске требуется место для частей и распакованного
приложения плюс 512 МиБ запаса. Части сохраняются рядом с папкой назначения
в `.II-download-<идентификатор>`. Для докачки выберите ту же папку назначения.
После успешной установки части удаляются, если включена соответствующая опция.
Удаление приложения: закройте II, удалите его папку и ярлык. Сначала сохраните
собственные результаты и материалы из `data`, если они нужны.

## Сборка

```powershell
.\.venv\Scripts\python.exe scripts/build_installer_payload.py `
  --source 'G:\II-installer-build-20260927\source\II-portable' `
  --output 'G:\II-installer-build-20260927\release' `
  --base-url 'https://github.com/dydosux/II-downloads/releases/download/v2026.09.27'
./scripts/build_installer.ps1 -Manifest 'G:\II-installer-build-20260927\release\manifest.json'
```

Папка `--output` должна быть новой. Упаковщик исключает журналы, историю обучения,
кэш Python и пользовательские входы/выходы ComfyUI. Файлы секретов и непустой
`data/train.jsonl` останавливают сборку для проверки. Корневой `.env` не входит.
Каждая часть меньше 2 ГиБ; исходный RAR сохраняется без изменений.

В `scripts/Installer.cs` находится весь исходный код установщика. SHA-256 встраиваются
при компиляции; подмена удалённого `manifest.json` не меняет доверенные хеши.
Установщик не имеет цифровой подписи издателя. Контрольные суммы подтверждают
целостность скачивания, но не заменяют подпись Windows.

## Проверка и публикация

Сначала скомпилируйте тестовый EXE в `build/installer-test/II-Setup.exe`, передав
манифест сборки, затем запустите:

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_installer -v
```

Тесты используют локальный HTTP-сервер и проверяют скачивание, Range-докачку,
разрыв соединения, испорченный кэш, неверные хеши, запрет выхода из папки при
распаковке и сохранность существующей установки. Диагностический режим
`--test-install MANIFEST DESTINATION BASE_URL RESULT_FILE` не запускает II.exe.
Обычный режим использует только встроенный манифест и HTTPS.

Публикуйте EXE, все части, manifest.json, SHA256SUMS.txt и лицензию модели в одном
GitHub Release. До проверки размеров и серверных SHA-256 сохраняйте релиз черновиком.
Прямая ссылка после публикации:
https://github.com/dydosux/II-downloads/releases/download/v2026.09.27/II-Setup.exe

## Текущая фоновая публикация

Файлы выпуска подготовлены в `G:\II-installer-build-20260927\release`.
Полная пробная установка проверена в `G:\II-installer-build-20260927\verified-install`.
Результат: `full-install-result.txt` со значением `OK`.

Текущая публикация использует `scripts/transfer_blocks.py`: файлы передаются
блоками по 32 МиБ. Подтверждённые блоки сохраняются при повторном запуске.
GitHub Actions `assemble-release.yml` восстанавливает пять исходных частей,
проверяет их SHA-256, удаляет временные блоки и публикует готовый релиз.
Встроенный манифест установщика остаётся прежним. Текущее состояние:

```powershell
Get-Content 'G:\II-installer-build-20260927\publish-status.json'
Get-Content 'G:\II-installer-build-20260927\transfer-progress.json'
Get-Content 'G:\II-installer-build-20260927\blocks-fast.log' -Tail 10
```

`published` означает готовность, `uploading_blocks` — передачу блоков.
Сборка на сервере отслеживается в GitHub Actions. Пока загрузка не закончилась,
ПК должен оставаться включённым и подключённым к интернету. Если процесс
передачи блоков прервался, повторный запуск пропустит уже проверенные файлы:

```powershell
.\.venv\Scripts\python.exe scripts/transfer_blocks.py upload
```

Не запускайте второй процесс публикации одновременно с работающим первым.
Обычный `publish_installer.py` пригоден для прямой загрузки при быстром стабильном
соединении, но одновременно с передачей блоков его запускать не следует.
